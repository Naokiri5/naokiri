## 2. Four Mandatory Pre-Merge Architectural Refinements​
​
1. **Net Balance-Delta Attribution Over Instruction Parsing (Solana):**​
   Solana whales route through multi-hop Jupiter split-routes, Jito tip bundles, and
Pump.fun-to-PumpSwap/Raydium migrations. `walletProfiler.ts` and `observations.ts`
compute net asset changes directly from confirmed `preTokenBalances` and
`postTokenBalances` (plus native SOL lamport deltas minus priority/Jito fees) per
transaction signature via `normalizeSolanaSwapFromBalances()`.​
2. **Unrealized "Dead-Bag" Penalty in Whale Scoring (`WIN-02`):**​
   Whales in Solana memecoins frequently hold illiquid or rugged tokens indefinitely
without selling. `profileWhaleWallet()` marks open unclosed lots to current executable pool
liquidity (`unrealizedBagPnlUsd`, defaulting to `0` if liquidity is pulled), quarantines wallets
with orphan sells (`coverageRatio < 0.85`), quarantines sub-3-second MEV/sandwich bots
(`medianHoldingMs < 3000`), and penalizes strategies that collapse under a `+2,500ms`
execution lag (`lagResilienceRatio`).​
3. **Protecting the 4ms `SwarmThreadPool` Hot Path:**​
   Helius/Geyser WebSocket stream parsing, Token-2022 RPC security checks
(`screenSolanaMint()`), and Jupiter V2 quote fetches run inside dedicated async I/O
workers. A `WhaleObservation` is published into `NexusFabricRouter` only *after* transaction
confirmation and fail-closed safety screening pass so the 100-agent swarm loop never
stalls.​
4. **Strict PR Reconciliation Order (`PR #95` -> `PR #46` -> `PR #50`):**​
   - **Step 1 (`PR #95`):** Merge provider HTTP/WS transport abstractions, Helius/RPC
rate-limiters, and deadline timeouts into `server/src/providers/`.​
   - **Step 2 (`PR #46`):** Merge base Solana RPC client, `confirmed` vs. `finalized`
commitment helpers, and base58 decoders into `server/src/solana/`.​
   - **Step 3 (`PR #50`):** Merge Solana mint-safety checks into `server/src/safety/safety.ts`
and expose `screenSolanaMint(mintAddress, inspector, now, policy)`.​
