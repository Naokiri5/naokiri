# **MIA AUTOPILOT — Engineering Questions, Reality Check & Code Implementation Master Prompt**

Before giving Claude or Codex another 100 features to build, I would make it answer one central question:

**“If I close my laptop tonight, will MIA still operate correctly, protect the account, recover from failures, and explain every decision when I return tomorrow?”**

That is a much stronger development target than simply making the dashboard look impressive.

## **1. The difficult truths MIA's engineers need to confront**

Based on your uploaded 100-upgrade plan and the GitHub repository:

1. **100 market workers do not automatically create a profitable strategy.** MIA's documentation reports weak out-of-sample results for its initial strategies. More analysis isn't a substitute for demonstrated trading performance.
2. **A working dashboard is not proof of a reliable automated trading system.** A 24/7 service needs independent hosting, recovery, monitoring, durable state, and failure testing.
3. **An AI assistant should not control everything.** Trader Joe can explain decisions and coordinate safe operations, but financial authorization and risk enforcement must remain independent.
4. **Instant withdrawals cannot be guaranteed.** A withdrawal request can be fast, but actual settlement depends on the provider, account restrictions, security checks, and payment or blockchain network.
5. **Adding all 100 upgrades at once would introduce unnecessary risk.** You need a verified baseline, code ownership, small implementation batches, and regression testing.
6. **The floating window should never be responsible for running the bot.** Closing the window must not interrupt background monitoring or permitted paper trading.

Your repository already contains the React frontend, Fastify backend, market scanners, risk engine, paper trading, and other components. PR #7 and PR #8 are currently open, so their work must be reconciled before adding overlapping functionality.

The objective should be **a system that is measurable, recoverable, understandable, and safe to leave running unattended in paper mode**—not merely a system with an impressive list of features.

## **4. Example: How an idea becomes functioning code**

Here is how Claude should translate four of your upgrades into concrete development work.

| Upgrade                                 | How it functions                                                                                                                                              | Where the code belongs                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |

**User requirement**

“I want to see my profit while working.”
