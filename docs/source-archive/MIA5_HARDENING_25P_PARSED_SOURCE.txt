6. Execution, Venue Routing & Crash-Recovery
Lifecycle
6.1 Order Intent State Transitions
 1.​ INTENT_RESERVED: Written atomically inside
     CanonicalRiskGate.evaluateAndReserveIntent() before any network call. Counts
     immediately toward symbol, sleeve, and global exposure caps.
 2.​ SUBMITTED: Written via riskGate.recordExchangeSubmission() once the venue returns
     an exchangeOrderId (or recovers an existing exchangeOrderId on duplicate
     clientOrderId retry).
 3.​ PARTIAL_FILL / FILLED: Written via riskGate.recordFillUpdate() on immediate fill
     (PaperOmsAdapter), WebSocket execution report
     (LiveOmsAdapter.handleVenueExecutionReport), or startup reconciliation
     (reconcileStartupIntents).
 4.​ REJECTED: Written via riskGate.releaseFailedReservation() ONLY when an
<PARSED TEXT FOR PAGE: 21 / 25>
    INTENT_RESERVED order fails before exchange acceptance or is confirmed absent on the
    exchange during startup reconciliation.
6.2 Sleeve-to-Venue Routing & clientOrderId Formatting
 ●​ futures & spot: Routes to preferredCryptoVenue (binance using newClientOrderId up to
    36 chars, or okx using alphanumeric clOrdId stripped of underscores/hyphens and sliced
    to 32 chars).
 ●​ stocks_etf: Routes to alpaca using client_order_id (up to 36 chars).
 ●​ memecoin & yield: Routes to the isolated solana signer enclave (signerWebhookUrl)
    using clientOrderId (up to 36 chars).
6.3 Startup Boot & Reconciliation Sequence (buildMiaServer)
 1.​ Open ./data/mia_ledger.sqlite in WAL mode and initialize all schemas.
 2.​ Seed risk_policy_limits (1.0x caps in PAPER, 0.25x caps in LIVE) with a 45-second lease
     (POLICY_TTL_MS = 45_000). Guardian Shield remains HALTED.
 3.​ Run reconcileStartupIntents() across all rows in INTENT_RESERVED, SUBMITTED,
     PARTIAL_FILL, or RECONCILE_REQUIRED:
 ○​ INTENT_RESERVED + not found on exchange → releaseFailedReservation() (resolved++).
 ○​ SUBMITTED / PARTIAL_FILL + not found on exchange → unresolved++ (flags mismatch for
      manual audit).
 ○​ Found as FILLED on exchange → recordFillUpdate(..., true) (resolved++).
 ○​ Found as CANCELLED / REJECTED on exchange → records partial fill if filledNotionalUsd
      is greater than 0, otherwise releaseFailedReservation() (resolved++).
 ○​ Still OPEN or PARTIAL_FILL on exchange → updates fill progress and increments
      unresolved++.
 4.​ Post-Reconciliation Gate:
 ○​ If unresolved is greater than 0 → trips Guardian Shield to HALTED and dispatches
      webhook alert to OPS_WEBHOOK_URL.
 ○​ Else if MIA_TRADING_MODE === 'PAPER' → calls
      riskGate.armGuardianShield('startup_paper_auto_arm').
 ○​ Else (MIA_TRADING_MODE === 'LIVE') → keeps Guardian Shield HALTED
      (LIVE_MODE_AWAITING_OPERATOR_STEP_UP_ARM) until operator submits a fresh wallet
      signature to POST /api/guardian/arm.
