# Decision Twin

Pure twin.ts reuses lab/exits.ts; no OMS/database/policy imports. API POST /api/ditas/twins accepts {eventId,candles,sourceReference,assumptions:{feeRate,spreadBps,slippageBps,notional,maxParticipationRate,entryDelayBars?}}. Frozen plan comes from immutable proposal/decision event, never the request. Decision-time quality must not have failed. API requires uploaded history to begin at the first full bar opening after recorded decision and include only closed bars as of request clock. Max2000 consecutive bars. Owner cannot inject decision-time liquidity; service derives it from stored ask depth and timestamp.

Output is HYPOTHETICAL: shadow next-open, delayed-entry counterfactual, WAIT0. Stops and absolute targets stay frozen; entry gaps can invalidate the plan. Costs include fees, spread/slippage both ways. Opening participation is capped by decision-time depth; absent/stale/future depth => NO_FILL, capacity may yield partial entry. Shared stop-first gap/trailing/time rules apply. OPEN/censored positions have null total PnL/R; realized and marked unrealized estimates remain distinct. Closed-only differences calculate avoided-loss/missed-gain estimates.

Persist only in immutable ditas_twin_runs, never actual orders/positions/financial ledger. Records include all assumptions, sourceReference and history SHA256; uploaded provenance is OWNER_UPLOADED_UNVERIFIED. Queue priority, exit depth, evolving liquidity/spreads and financing are not modeled. Results are conditional research outcomes, not guaranteed fills. Additional alternative strategies/stops/exits and aggregate opportunity-cost certification remain pending. No automatic strategy changes.
