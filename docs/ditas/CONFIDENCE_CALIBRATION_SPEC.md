# Confidence calibration

Pure calibrationReport implements Brier, clipped log loss, weighted ECE, reliability bins, Wilson95% observed-frequency intervals and explicit sample uncertainty. Default100 total forecasts and20/bin. Sparse total => UNCALIBRATED; sufficient total => EVALUATED, never automatic CALIBRATED approval. Evidence strength/agreement/quality/execution feasibility remain separate and no vote-derived probability exists.

POST /api/ditas/forecasts requires frozen event within60 seconds (clock rollback rejected), explicit probability, future timeframe-aligned targetAt, referencePrice equal frozen proposal entryRef, modelVersion and promptVersion. Target is CLOSE_ABOVE_REFERENCE at targetAt. Server timestamps forecast registration; retrospective registration is rejected. Immutable cohort includes market class, strategy/version, timeframe, model/prompt, target definition horizon bars and a five-second registration-lag bucket. Unique dedupe key prevents repeated same instrument/strategy/model/target forecasts across proposal/decision copies.

POST /api/ditas/outcomes requires forecastId, observedPrice, observedAt exactly targetAt, sourceReference; server rejects early/future or duplicate observation. Label derived from frozen target rule, not user-supplied success boolean. Observations are OWNER_REPORTED_UNVERIFIED; no independent-source certification is claimed. Forecasts/outcomes are immutable. GET /api/ditas/calibration?cohort=exact reads a single cohort. Default dashboard does not pool cohorts. This provides metrics on operator records, not validated AI forecasting skill. Overlapping outcomes reduce effective sample size even with deduplication; independent prospective samples and validation remain necessary.
